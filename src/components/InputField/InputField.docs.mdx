# Input Field

Input fields allow users to enter and edit text. Figma component set `99:960`. Supports **default**, **ghost**, and **filled** value states, 2 sizes, 5 types, and error action with accessible validation messaging.

## Practical input kinds

Pass **`inputKind`** so each field uses the right HTML `type`, mobile keyboard, `autoComplete`, and character filtering:

| `inputKind` | Use for | Behavior |
| ----------- | ------- | -------- |
| `email` | Email addresses | `type="email"`, email keyboard, strips spaces |
| `phone` | Phone numbers | `type="tel"`, telephone keypad, digits / `+` / `()` / spaces only |
| `url` | Websites, copy fields | `type="url"`, URL keyboard |
| `name` | Person or business names | Letters, spaces, `'`, `.`, `-` only |
| `search` | Lookup / filter fields | `type="search"`, search keyboard |
| `amount` | Currency | Decimal keypad, digits / `.` / `$` |
| `number` | Quantities | Numeric keypad, digits only |
| `text` | General text | Default (no filtering) |

## Usage Guidelines

- **Do**: Always include a label for accessibility
- **Do**: Provide hint text to clarify what the user should enter
- **Do**: Set `inputKind` to match the data you collect (`email`, `phone`, `url`, etc.)
- **Do**: Use the error action state with a descriptive error message
- **Don't**: Use placeholder text as a replacement for labels
- **Don't**: Disable inputs without explaining why
- **Accessibility**: The input is linked to its label via `htmlFor`/`id`
- **Accessibility**: Hint text is connected to the input via `aria-describedby`
- **Accessibility**: Error state sets `aria-invalid` on the input element
- **Accessibility**: Focus ring uses `box-shadow` for visible focus indication
